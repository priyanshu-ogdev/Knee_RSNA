# RSNA 2024 Knee Abnormality Detection: Architecture & Pipeline Design

This document provides a highly detailed, comprehensive review of the state-of-the-art (SOTA) baseline repository stored in src/. It breaks down the foundational architecture, the targeted upgrades that elevated it to the top of the Kaggle leaderboard, and the final inference optimizations necessary to hit the **0.943** threshold.

---

## 1. The Foundational Baseline (src/model.py)
At its core, predicting 12 different knee conditions (from ligament tears to osteoarthritis) requires a model that understands both dense global context and fine local structures.

* **The Backbone:** The foundation uses the HuggingFace dinov2-small Vision Transformer. DINOv2 provides incredibly robust, self-supervised feature embeddings.
* **Surgical Fine-Tuning:** Vision Transformers are notoriously data-hungry and prone to catastrophic forgetting if fully unfrozen on small medical datasets. To counteract this, the baseline aggressively **freezes** the vast majority of the network. Only the **last 6 transformer blocks** and the final LayerNorm are allowed to update (UNFREEZE_LAST = 6).

---

## 2. Preprocessing & Data Upgrades (src/dataset.py)
Handling raw 3D DICOM volumes is the biggest hurdle in medical imaging. The pipeline implements three critical upgrades to standardize the data.

* **Upgrade 1: Physical Millimeter Cropping**
  Standard image processing uses fixed pixel crops (e.g., center 224x224). Because MRI scanners operate at vastly different resolutions and field-of-views, a fixed pixel crop might capture the entire knee on one scanner, but only a zoomed-in patch of cartilage on another. 
  **The Fix:** The script reads the PixelSpacing metadata directly from the DICOM headers. It dynamically calculates the exact number of pixels required to achieve a **physical 130.0 mm crop** (CROP_MM = 130.0). This guarantees the anatomical scale is invariant before resizing the tensor to 336x336.
* **Upgrade 2: Laterality Normalization**
  Right knees are horizontally flipped across the Coronal and Axial planes so that they structurally mirror Left knees. This effectively halves the spatial variance the model needs to learn.
* **Upgrade 3: The 6-Slot Matrix**
  Rather than processing massive unorganized 3D volumes, the dataset.py extracts exactly 3 slices from the center of 6 standardized acquisition planes (Sagittal T1, Coronal Fluid, Axial Fluid, etc.). This ensures the model always receives consistent anatomical anchors.

---

## 3. The SlotHead Routing Upgrade (src/model.py)
Standard classification pipelines flatten the backbone's feature maps and push them through a linear Global Average Pooling (GAP) layer. For complex 3D knees, this destroys spatial context.

* **The Fix:** The baseline implements a custom attention-pooling mechanism called SlotHead. 
* **How it works:** It uses an einsum-based attention layer with learnable queries tailored to the 12 target diseases. The SlotHead dynamically "routes" the embeddings from the 6 standardized anatomical slots directly to the relevant disease classifiers (e.g., forcing the model to look heavily at the Sagittal slot when classifying an ACL tear).

---

## 4. Optimization & Training Upgrades (src/train.py)
The training loop contains several distinct upgrades to handle noisy Kaggle labels and strict hardware limits.

* **Upgrade 1: NLP-Confidence Weighted Loss**
  The provided labels in this competition were generated by an NLP algorithm reading radiologist reports, meaning some labels are highly confident, while others are ambiguous guesses. The 	rain.py loop implements a custom **Weighted Binary Cross Entropy Loss**. Highly confident labels receive a weight of 1.0, while ambiguous labels drop to .25, preventing the model from heavily penalizing itself on bad ground truth.
* **Upgrade 2: Dual Learning Rates**
  The optimizer (AdamW) uses a split learning rate. The delicate, pre-trained dinov2 backbone is updated very slowly (8e-6), while the newly initialized, randomized SlotHead is trained rapidly (1e-3). 
* **Upgrade 3: The 8-Hour Safety Trigger**
  Kaggle terminates any run exceeding 9 hours. The loop tracks 	ime.time() against a hardcoded TIME_BUDGET_HOURS = 8.0. It performs an early stop when triggered, guaranteeing 1 hour remains for the inference logic to execute and save the submission.

---

## 5. Inference & The 0.943 SOTA Upgrade (src/inference.py)
A standalone dinov2 model trained for 8 hours peaks around **0.938**. Pushing the score to **0.943** requires aggressive optimization and ensembling during the final inference hour.

* **Speed Optimizations:** The predict() function relies on 	orch.inference_mode() and 	orch.autocast('cuda') (Automatic Mixed Precision) to maximize GPU throughput over the massive hidden test set.
* **The 0.943 Upgrade: Rank Ensembling**
  To hit 0.943, the script merges our dinov2 predictions with external, pre-trained CoAtNet predictions. However, directly averaging probabilities between a Transformer and a CNN causes calibration collapse. 
  **The Fix:** The 
ank_ensemble() function converts all probabilities into **percentiles** (pd.Series.rank(pct=True)) before blending them, completely bypassing calibration drifts.
* **Target-Specific Blending:**
  Transformers excel at global context (Effusion), while Convolutional networks (CoAtNet) excel at sharp, local edges (Fractures, Meniscus tears). The inference script exploits this by weighting the blend dynamically:
  * For global diseases, it blends 40% DINOv2 / 60% CoAtNet.
  * For localized tears (**Lateral Meniscus**, **ACL**, **Fracture**), it violently overrides the blend, assigning 75% to 100% of the decision weight to the CoAtNet predictions.
